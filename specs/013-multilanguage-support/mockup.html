What this mockup covers

  • Header language switcher placement: a labeled pill (flag + language name) sitting before the theme toggle, in the same right-hand cluster (FR-001, FR-002) — flag and name together rather than a code or icon alone, since (unlike light/dark) no single icon reads as "currently active language," and a flag alone isn't reliably readable as a language.
  • Clicking a menu option actually re-renders the sidebar labels, header title, role badge, sign-out label, and dashboard card copy in the canvas, standing in for the real translate pipe reacting to the active-language signal with no reload (FR-003).
  • The email correspondence language field lives on Settings › Preferences (not Profile) — visually and structurally separate from the header switcher, with the "not set → falls back to default" hint (FR-006, FR-008) that disappears once a value is explicitly chosen (FR-009 — the two settings don't affect each other).
  • Desktop vs. mobile — the language switch pill drops its text label on mobile, keeping just the flag, the same way the sidebar's brand name and nav labels shrink.

Out of scope for this mockup (see spec.md / design.md): persistence across visits (FR-004), the actual translated dictionaries for every screen (US3/FR-011 — content completeness, not layout), and the rest of the existing Settings › Preferences "Coming soon" placeholder (account/currency/notification settings), unchanged by this feature.
