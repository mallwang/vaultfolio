Vaultfolio Holdings — layout review (003-manual-holdings-entry)

Updated for the 2026-08-28 clarifications session: every holding now requires a Management source; ETF and Gold submissions update an existing row in place instead of always adding a lot; Gold is now weight-in-grams only (no unit/purity) plus an optional current value; ETF has no purchase date field at all; and the list gets a new value-distribution panel.

Try the asset-type selector inside "Add holding" — it swaps the field set live, the same way the real form would. Toggle viewport to check the dialogs and table on narrow widths. Real PrimeNG components (incl. p-chart), routing, and persistence are not present here — this only demonstrates layout, hierarchy, and states.

Out of scope for this mockup

  • Editing ETF/Share/Gold holdings — same pattern as "Edit — Bitcoin" (locked asset type, only that type's fields, incl. Management) but not separately mocked for every type.
  • Loading states, network errors, and the "already deleted elsewhere" edge case — resilience behavior, not layout.
  • Sorting/filtering the holdings list for large portfolios (Edge Cases) — interaction detail for the real implementation.
  • Real form validation logic, persistence, routing, and the real Chart.js-backed p-chart rendering (the donut here is a static CSS conic-gradient stand-in) — every state here is static or client-side-only (the type selector).
