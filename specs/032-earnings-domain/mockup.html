Earnings domain

Static layout review for the Earnings domain before planning. All figures are invented example data (two fictional employers, 2012–2026) and do not come from any real payslip. Use the controls to switch screen, language, theme and viewport. Chart bars and grid cells are clickable and open the month detail.

Layout decisions to review

  • The long single page of earnings-evolution is split into four sub-tabs: Overview (summary, KPIs, charts, month detail), Tables (year × month grid, taxes per year, wage-tax certificates), Data check and Imports (history, employer names, privacy, delete). Import itself is a primary action in the toolbar, like "Add holding".
  • KPI tiles compare the incomplete latest year with the same months of the previous year (Jan–Sep 2026 vs. Jan–Sep 2025) instead of the full previous year, so a partial year doesn't show as a drop.
  • A data-check problem is surfaced on the Overview as a warning strip with a link, and as a count badge on the Data check tab.
  • The import preview lists every selected file with its own outcome. Rejected and duplicate files are skipped; the confirm button names how many files will be saved. One row can be expanded to show exactly which figures will be sent.
  • Series colors keep the five validated roles from earnings-evolution: net (blue), taxes (orange), social insurance (teal), regular pay (indigo, the app primary) and bonus (red).

Out of scope for this mockup

  • Confirmation dialogs for deleting an import or all data, and the rename save flow — plan-time details.
  • Export control contents (shared 029 capability, shown only as the button).
  • Loading/progress while parsing is shown once (progress bar in the import preview); real timing is plan-time.
