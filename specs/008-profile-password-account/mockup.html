Traceability — Profile card: FR-001, FR-004 (display name, header updates with no reload). Email card + "Email change pending" state: FR-002, FR-003 (superseding request, old address stays active, conflict rejection is a form error not separately mocked). Password card + "wrong current password" state: FR-005, FR-007. Danger Zone's three dialog states: FR-008–FR-010 (optional export, explicit final confirmation, shared last-admin invariant reused from 006's Accounts tab). Forgot/reset/expired standalone pages: FR-006, SC-002, SC-003 (identical response regardless of account existence; one shared expired/used page for both token purposes per the spec's Key Entities section).

Not shown / out of scope for this mockup

  • The email-change verification link's own success confirmation (mirrors sign-in).
  • Server-error state during deletion (FR-010) — same form-alert pattern as 006/007, not a new screen.
  • Timing-attack resistance of the forgot-password response (server-side, no UI).
