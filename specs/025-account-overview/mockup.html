This is a static, non-functional mockup for design review — no data is saved, no backend is called.

What this covers

  • US1 (P1): a reference list per account — name, category, provider (linked), purpose, and a couple of free-text detail fields — grouped with a per-category count (FR-001, FR-002, FR-009).
  • US2 (P2): add/edit/delete affordances on every row, and the required-name validation error (FR-003–FR-006).
  • US3 (P3): categorization is optional — the "Uncategorized (flat)" screen shows the same page with no category structure at all (FR-007, FR-008).
  • Edge cases: the empty state before any account exists.

Note — this revises the reviewed spec

  • The original spec.md described balances, totals, and per-category subtotals; this feedback replaces that with a purely descriptive reference (no money at all), plus provider links and a couple of named free-text fields ("card usage", "required minimum"). spec.md and design.md are being updated to match before planning proceeds.

Not shown here (out of scope for this mockup)

  • Delete confirmation dialog copy/behavior (FR-005) — the row-level delete icon is shown, the confirmation step itself is a plan-time detail.
  • Exact category-filter interaction (dropdown vs. tabs vs. always-grouped) — FR-009 only requires grouping-or-filtering; this mockup shows the grouped variant.
